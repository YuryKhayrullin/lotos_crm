# Этап 9: матрица локальной приёмки

Область: согласованные сценарии `CRM_BACKEND=postgres`, desktop/mobile Chromium. Не разрешение production-релиза и не обещание покрытия всех возможных сочетаний входных данных.

## Записи и восстановление

Все **21** перечисленные операции включены в параметризованную SQL-матрицу [recovery.test.ts](../tests/postgres/recovery.test.ts). Для каждой проверяются строгий отказ неизвестного поля до создания намерения, обычное подтверждение, новая инстанция router после потерянного ответа, rollback при отказе аудита, восстановление исходного намерения и отсутствие второго маркера. Подтверждённый результат проверяется без повторного применения старого состояния.

| Сценарии    | Действия                                                                                              | Дополнительные проверки                                                                                                                                                 |
| ----------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Справочники | createBranch, createClient, createCoach, updateClient, deleteClient, deleteCoach                      | Версии, архивирование, пустая карточка, поиск/страницы, исходная оплата; [domain.test.ts](../tests/postgres/domain.test.ts)                                             |
| Расписание  | createLesson, createLessonWithClients, updateLesson, cancelLesson, deleteLesson, assignClientLesson   | Владение, филиал, пустой/неизвестный состав, запрет отмены после любой отметки, FK/версии; [schedule-attendance.test.ts](../tests/postgres/schedule-attendance.test.ts) |
| Учёт        | recordPayment, recordAdjustment, repairLessonLedger                                                   | Точные копейки, допустимые остатки, полный audit fingerprint, запрет выдуманных платежей; [accounting.test.ts](../tests/postgres/accounting.test.ts)                    |
| Доступ      | assignUserBranch, activateUser, deactivateUser, resetCoachPassword, revokeUserSessions, linkCoachUser | Актуальные права, отзыв сессий, старые повторы, конкуренция, rollback; [auth.test.ts](../tests/postgres/auth.test.ts)                                                   |

Для `createCoach` с доступом и `resetCoachPassword` матрица дополнительно проверяет отсутствие plaintext-пароля в intent, запрос исходного пароля для незавершённой попытки и CONFLICT при другом пароле. Подтверждённая операция восстанавливается **без** пароля. После обработки очищается private payload.

Посещаемость и документы имеют отдельные процедуры:

- `recordAttendance` / `recordBulkAttendance`: целый пакет, версии, correction/refund, последний остаток, старый повтор, reload и acknowledgement; [schedule-attendance.test.ts](../tests/postgres/schedule-attendance.test.ts), browser coach flow.
- `uploadReceipt`: намерение/приватные байты/SQL-привязка, исходный хеш, собственный доступ, закрытие без удаления, более новая версия, SQL-сбой до подтверждения и reload; [documents.test.ts](../tests/postgres/documents.test.ts), mobile browser receipt flow.

Общий механизм закрытия проверяется [domain.test.ts](../tests/postgres/domain.test.ts): чужой администратор не читает/не восстанавливает intent, незавершённый закрытый ключ больше не пишет, подтверждённые записи не удаляются. Одни и те же блокировки и проверки состояния используются domain/account writer; тест закрытия не считается отдельным UI-тестом каждой кнопки.

## Чтения и состояние интерфейса

| Экран/состояние                                                                                | Подтверждение                                                                                                                        |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Вход, отказ пароля, выход, недоступный session service, отзыв сессии                           | Node auth-store regressions, PostgreSQL auth, реальные Next HTTP/browser                                                             |
| Расписание, день/неделя, пустой день, ошибки, переходы дат                                     | Node interface/date/coach regressions и native browser calendar                                                                      |
| Московские даты при timezone браузера Los Angeles                                              | Date-core regression и реальный native browser                                                                                       |
| Клиенты: поиск/страницы/сортировка, ошибка списка, создание/редактирование/архив               | Domain tests и interface regressions; реальный admin catalogue browser flow                                                          |
| Тренеры: профиль/аккаунт, pending, ошибка чтения, назначение/активация, сброс/отзыв            | Interface regressions, auth/domain и browser account flows                                                                           |
| История/аудит/оплата: ошибка чтения отдельно от подтверждённой записи, неверный/неполный ответ | API-client/interface regressions, accounting/domain и browser finance flow                                                           |
| Файл: ошибка проверки попыток не считается пустым результатом                                  | ClientReceiptPanel и API response regressions, документы/реальный mobile reload                                                      |
| Смена пользователя и поздний ответ                                                             | Auth/root/API regressions: read epoch, mutation identity, отменённые эффекты; последующий аккаунт не получает старые карточки/ошибки |
| Неизвестный исход и повторный конфликт 4xx                                                     | API-client regression: ранее неизвестная попытка сохраняет прежний ключ, не разрешает новую семантику                                |

Серверные read allowlists, branch scope и отсутствие финансовых/лишних персональных полей тренеру проверяются domain/auth suites. Нет единого притворного теста «все API всегда безопасны»: каждой категории соответствуют отдельные утверждения.

## Клавиатура и диалоги

[auth-http.test.ts](../tests/postgres/auth-http.test.ts) в browser-режиме проверяет:

- Enter при входе и открытии карточки/занятия; реальные кнопки доступны Tab, сортировка имеет кнопки и aria-sort.
- Удержание Tab/Shift+Tab в создании клиента, редактировании, профиле, продлении, корректировке, создании тренера, создании занятия, управлении занятием, посещаемости и управлении филиалами.
- Escape и возврат фокуса к открывшей кнопке для карточки, вложенных форм и занятия. Родительский профиль и вложенные формы используют настоящую вложенность Dialog Root, а не конкурирующие sibling-модалки.
- Возврат фокуса к заголовку recovery после удаления обработанной строки; пароль повторной попытки очищается после результата.
- Наличие recovery-панели у тренера после bootstrap/reload: она подписана на наблюдаемую готовность данных, а не только на ненаблюдаемый API-флаг.

Тест ожидает начальный focus handoff портала **до** нажатия Tab. Видимость попапа сама по себе не означает, что передача фокуса уже закончилась. Проверка удержания фокуса после каждой клавиши сохраняется.

## Чего эта приёмка не означает

Safari/WebKit, публичный staging, реальная пользовательская приёмка, нагрузка, backup/restore и эксплуатационные проверки остаются последующими этапами. Публичная регистрация по умолчанию выключена до D-09. Массовые операции серии, спорные права изменения старого состава и исправления архивных клиентов не утверждены автоматически.

Актуальные команды, фактические количества последнего полного прогона и границы тестового импорта: [UI_IMPORT_POSTGRES.md](UI_IMPORT_POSTGRES.md). Фильтр `LOTOS_TEST_NAME_PATTERN` служит только локальной диагностике; отфильтрованный прогон никогда не суммируется как полная приёмка.
