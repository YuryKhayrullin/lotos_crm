# Этап 11: безопасность, сбои и измерения

Дата: 9 октября 2026 года. Ветка `migration/postgres-webapp`. Проверки выполнены на отдельных одноразовых PostgreSQL/Test и вымышленных данных; Local, GAS, Supabase и production не переключались. Этап 10 этим не закрывается: владелец явно отказался от создания Local-администратора агентом и создаёт его вручную; постоянный импорт не выполнен.

## Что изменено

- Next.js и ESLint config закреплены на **16.3.8**, security patch внутри выбранной ветки. Установлены совместимые исправления `brace-expansion`/`source-map-js`; для жёстко закреплённого транзитивного `mysql2` добавлен override **3.24.5**, без смены major Prisma и без `audit fix --force`. Основание исправления Next — [официальный advisory](https://github.com/advisories/GHSA-4jqv-mc3x-m676).
- Посещаемость блокирует строки клиентов одним параметризованным SQL в стабильном порядке. Журнал и платежи для сверки читаются двумя пакетными запросами, после блокировок. Арифметика, fingerprint и весь transaction/rollback остаются прежними; глобального кеша остатков нет. По сравнению с исходным замером пакета из 20 учеников число SQL уменьшилось **177 → 120**, на 32%. Записи текущих отметок, событий, журнала, версий и подтверждения всё ещё обязательны — оптимизация не отключает аудит.
- Расписание переиспользует Intl-форматтеры внутри одного запроса, не кеширует приватные DTO между пользователями. Часовой пояс и права не меняются.
- Добавлены минимальные `/api/health/live` и `/api/health/ready`, `no-store`; ready проверяет миграцию, приватность/доступность документов и свободное место. Не чинит права, не показывает пути/версии/секреты. На публичном Caddy readiness закрыт; внутренний контейнерный probe обращается к приложению напрямую.
- Отключён `X-Powered-By`. Для HTML реализована **nonce-based script CSP** через `proxy.ts`: 32 случайных байта на запрос, `strict-dynamic`, без `unsafe-inline`/`unsafe-eval` для production-скриптов, запрет обработчиков через `script-src-attr`, объектов, base tag и framing. Входные nonce/CSP не принимаются; prefetch не обходит политику, а исключения matcher ограничены точными API/assets, не произвольными страницами с префиксом `icon`. Root layout динамический, HTML не кешируется совместно. Скрипты внешней аналитики больше не вставляются. **Style CSP допускает unsafe-inline** для существующих React/Base UI стилей — не выдаём это за полный запрет inline CSS. Development отдельно допускает eval/HMR; локальный production HTTP не перенаправляет ресурсы на несуществующий HTTPS.
- Проверено воспроизведение `deepmerge-ts` stack exhaustion на версии 7.1.5, затем добавлен точечный override **8.0.2**. Это сознательный транзитивный major-upgrade: изучены breaking changes, проверены обычное слияние конфигураций, отсутствие изменения входов и реальная загрузка обоих Prisma-конфигов. Все SQL-наборы перепроверены; не использованы новые unsafe-merge entrypoints. Основания: [advisory](https://github.com/advisories/GHSA-ggr8-5vv4-36mx), [changelog](https://github.com/RebeccaStevens/deepmerge-ts/blob/main/CHANGELOG.md). Совместимость подтверждается для текущей закреплённой Prisma, не обещается для любых будущих версий.
- Подготовлены non-root standalone Docker runtime и отдельный миграционный образ, без env/XLSX/private artifacts в build context. Реально проверены сборка и запуск runtime с read-only root, без сети и без секретов внутри образа.

## Гарантии и доказательства

| Область               | Проверка                                                                                                                                                                   |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Авторизация           | Реальные сессии Better Auth, актуальные статус/роль/филиал/version; отключение, сброс и смена филиала отвергают старый доступ                                              |
| Прямые запросы        | Admin-only операции не доступны coach; создание/изменение/отмена ограничены согласованными правилами, финансовые DTO не возвращаются coach                                 |
| Посещаемость          | Проверка состава, rollback целого пакета, гонка последнего остатка, повтор после commit, старый повтор после исправления, stale versions                                   |
| Повторы/потеря ответа | Долговечные подтверждения, восстановление после reload и настоящего commit; закрытие намерения не отменяет подтверждённые данные                                           |
| Файлы                 | Защищённый маршрут, проверенные тип/размер/байты, versioned-привязка и recovery; испорченная восстановленная квитанция не выдаётся                                         |
| Запросы/вход          | Реальные байты до JSON, origin/CSRF, атомарные PostgreSQL-счётчики, игнорирование произвольного XFF                                                                        |
| HTML/CSP              | Настоящий Next HTTP: nonce в заголовке и script tags, уникальность, spoof/prefetch, регистрация/404; Chromium блокирует внедрённые script/onclick и сохраняет рабочий вход |
| SQL роли              | На отдельной БД **внутри Test-контейнера** выполнен настоящий role-init/restore; runtime не superuser и не может DDL/отключение audit/TRUNCATE, backup не может DELETE     |
| Восстановление        | Настоящие pg_dump/pg_restore в другую Test-БД, повторный вход, аудит и побайтная проверка квитанции; оригиналы не повреждаются                                             |

Команды для воспроизведения:

```bash
export PATH="$PWD/.tools/node/bin:$PATH"
npm run release:check
npm run test:postgres
npm run test:auth:postgres
npm run test:domain:postgres
npm run test:operations:postgres
npm run test:auth:browser
npm run test:infra:config
npm run security:secrets
```

PostgreSQL-наборы запускаем **последовательно**: каждый владеет своим временным контейнером, но использует выделенный test-порт. Не запускать одновременно генерацию Prisma и TypeScript по общему `.generated`. В CI добавлены operations и Compose config проверки. Отфильтрованные диагностические прогоны не суммируются с полными.

Последняя полная локальная приёмка после CSP/security override: **280 Node + 28 foundation/upgrade + 35 auth + 82 domain + 7 operations + 8 реальных Next HTTP + 15 Chromium/browser = 455**, без двойного подсчёта повторных прогонов. TypeScript, ESLint, форматирование и Webpack build прошли. Предыдущая приёмка 445 остаётся историческим срезом, не прибавляется к 455. Secret scan проверяет историю Git и текущие non-ignored файлы, но не является доказательством отсутствия любых возможных секретов.

**Ограничение повторной упаковки:** Docker runtime прежнего среза действительно проверялся, но пересборка после последнего override/CSP не завершена. В новом builder `npm ci` успешно установил пакеты; `prisma generate` остановился без прогресса, schema-engine отсутствовал, отдельный запрос к публичному engine-checksum endpoint получил таймаут. Агент остановил только свой промежуточный builder; код 137 здесь результат остановки, не доказательство OOM. Host production-build и все наборы выше успешны. Новый runtime tag не считать готовым release image; для self-hosted выпуска нужна успешная повторяемая сборка и контейнерный smoke. Текущий запланированный Vercel-вариант требует собственной cloud-приёмки, а не подмены её старым Docker-доказательством.

## Измерения

Один локальный процесс API router и настоящий PostgreSQL по TCP; **не интернет/HTTPS/browser latency**, не VPS benchmark. Фикстура: **5 000 клиентов, 1 000 занятий, roster 100, 500 исторических отсутствий**, без выдуманных платежей/списаний. Один warm-up исключён, затем 12 успешных измерений; p95 здесь nearest-rank, то есть максимальный из небольшого набора. Среда и фоновые процессы влияют на время.

| Операция                  | p50, мс | p95, мс | Максимум SQL | Максимальный ответ |
| ------------------------- | ------: | ------: | -----------: | -----------------: |
| Расписание: 1 000 занятий |  281.85 |  324.83 |            7 |       584 013 байт |
| Состав: 100 учеников      |   56.91 |   81.34 |           12 |        23 031 байт |
| Сохранение: 20 отметок    |  360.23 |  494.52 |          120 |         2 967 байт |
| История с аудитом         |   84.94 |  102.19 |           17 |       300 190 байт |

Отчёты создаются в ignored `.artifacts/performance-latest.json` и `.artifacts/restore-latest.json`, только агрегаты без SQL/параметров/персональных значений. Прогон ограничивает SQL round trips чтений и грубые зависания, а не устанавливает договорённый production SLO. Внутри посещаемости остаются необходимые индивидуальные записи; число запросов не обязано быть постоянным при изменении размера пакета.

Дополнительно добавлен настоящий HTTP smoke: 140 session-чтений, четыре параллельных клиента с двумя ролями, проверка изоляции и размера ответа. `.artifacts/http-load-latest.json` содержит только агрегаты. Это небольшой auth-набор и короткий прогон, не 5 000 клиентов через HTTP и не sustained/soak/SLO. UTF-8 oversized и chunked тело проверены через настоящий HTTP: 413 до JSON, без отражения входных данных. Браузерный инъекционный fixture использует CSP от настоящего Next-ответа; malicious HTML подставлен тестом, а не существует как публичный endpoint. DevTools `evaluate` не используется для вставки проверяемого вредоносного кода, поскольку это может обходить CSP.

История возвращает ограниченные текущие отметки и полный журнал для сверки; размер ответа ~300 КБ при длинной истории — отдельное направление пагинации отображения без отключения полного аудита. Sustained HTTP-нагрузка, несколько процессов, целевое железо VPS/Vercel, отказ сети/диска на реальном хосте и долговременный soak-test пока **не закрыты**.

## Остаточные security-риски

После последнего исправления `deepmerge-ts` `npm audit`: **5 high, 0 critical** (раньше 8 high, первоначально 12). `--omit=dev` теперь показывает **0 известных advisory**. Это результат проверки dependency graph, не доказательство отсутствия всех уязвимостей приложения, build/migrator image или инфраструктуры.

- `braces` в toolchain ESLint/fast-glob/micromatch: registry на дату проверки не предлагает исправленный совместимый релиз; audit предлагает неподходящий downgrade ESLint/Next. Не применён.
- Остальные high в списке — цепочка `braces → micromatch → fast-glob → @next/eslint-plugin-next → eslint-config-next`, не пять независимых эксплойтов. Эти build/CI зависимости не следует называть полностью безопасными только потому, что они не входят в omit-dev граф. Принятие остаточного риска владельцем не объявляется автоматически.

До публичного выпуска нужны проверенное устранение либо формальное, ограниченное по сроку принятие остаточного риска с обоснованием достижимости. Нужны также внешние alerts и нагрузочный SLO; полное ограничение inline styles — отдельный совместимый UI-проект. Успешные тесты не заменяют эти решения и не означают «никогда не упадёт».

## Переход к этапу 12

Конфигурация/инструменты подготовлены: [STAGING_RUNBOOK.md](STAGING_RUNBOOK.md). Публичного стенда/ссылки, настоящего сертификата, настроенного внешнего repository и доказанного восстановления с него **ещё нет**: VPS, домен, backup destination, RPO/RTO и оповещения не согласованы. Не выдаём локальный pg_restore за восстановление после потери VPS.

Владелец предложил временный Vercel вместо ещё не арендованного VPS. Реализованы отдельный cloud профиль (staging-only, exact Neon pooler/direct identity, verify-full TLS), pg pool/lifecycle, private Blob adapter, readiness/proxy, cloud-команды и профильный предел квитанций 3 МиБ. Self-hosted filesystem и его 5 МиБ не изменены. Потерянный Blob put-ответ, неизменность ключа/байтов, SQL-failure после сохранения объекта, возобновление через новый router и запрет coach-доступа проверены с тестовым транспортом и настоящим PostgreSQL. Это не настоящая облачная сеть и не подтверждение прав Vercel/Neon.

Обновлённая полная локальная приёмка cloud-адаптации: **287 Node + 28 foundation + 36 auth + 88 domain + 7 operations + 8 Next HTTP + 15 Chromium = 469**. Предыдущие 445/455 не прибавляются. TypeScript/ESLint/форматирование/secret scan/Compose config пройдены; Webpack production-build выполнен в явном cloud-профиле с вымышленными endpoint и без реальных credentials. `npm audit --omit=dev`: 0; полный audit: прежние 5 high в инструментальном графе, 0 critical. Реальные API-подключения, сертификат, pooler/Blob/платформенный IP, sustained HTTP-SLO и offsite cloud restore пока не выполнены. Доступ к Vercel/Neon не подтверждён, публикации/привилегированного bootstrap не было. Инструкция: [VERCEL_STAGING.md](VERCEL_STAGING.md); GO/NO-GO переключения: [CUTOVER_RUNBOOK.md](CUTOVER_RUNBOOK.md).
