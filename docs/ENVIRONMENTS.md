## Разделение окружений

| Окружение  | Файл настроек                             | База / роль                                          | Данные и хранение                                                                    |
| ---------- | ----------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Local      | `.env.db.local`                           | `lotos_crm_local` / `lotos_local`, `127.0.0.1:55432` | Разработка; собственный постоянный volume `lotos-crm-local_database`                 |
| Test       | `.env.db.test.local`                      | `lotos_crm_test` / `lotos_test`, `127.0.0.1:55433`   | Одноразовый случайный Compose-проект, tmpfs; удаляется после запуска проверки        |
| Staging    | `.env.staging.local`, пока отсутствует    | `lotos_crm_staging`, внутренний сервис `db`          | Только вымышленные данные; отдельные ключи, volumes и домен                          |
| Production | `.env.production.local`, пока отсутствует | `lotos_crm_production`, внутренний сервис `db`       | Рабочие данные; отдельные ключи, volumes, резервные копии и согласованный deployment |

Секреты local/test генерируются независимо через `crypto.randomBytes`, файлы создаются с правами `0600` без перезаписи существующих. Реальные `.env*`, `.tools/` и storage исключены из Git; безопасные `.example` остаются доступными.

Staging/production-шаблоны находятся в [infra/env](../infra/env). Они намеренно не проходят preflight без настоящих уникальных настроек. Runtime и migrator в шаблонах разделены; реальные роли и их права ещё не созданы. SQL-миграции добавлены локально на этапе 3, но не применялись к staging/production. Не создавать реальные конфигурации или запускать deployment по шаблону автоматически.

## Команды local/test

```bash
npm run env:init
npm run env:check -- local
npm run env:check -- test
npm run db:local:up
npm run db:local:status
npm run test:db
npm run db:local:stop
```

- `env:init` создаёт только local/test. Повтор не меняет действительные существующие файлы и пароли.
- `env:check` требует явно выбранное окружение, не делает сетевого подключения и не выводит URL с паролем.
- Для local/test разрешены только заданные loopback-порты, имена БД и роли. Удалённые адреса, Supabase, production-имя, произвольные connection options, неподходящий backend и несогласованные credentials отклоняются.
- Парсер запрещает дубли ключей и shell/env-подстановки. Compose получает проверенные значения, а не произвольный наследованный `DATABASE_URL`/`POSTGRES_*`/`COMPOSE_*`.
- Docker-действия разрешены только для local и одноразового test; staging/production CLI-команды up/stop отвергаются. Используется локальный Unix socket Docker, не удалённый Docker context. Подготовленные DB-команды рассчитаны на Linux/WSL с этим socket.
- `db:local:stop` останавливает только local, сохраняя volume. Команд удаления постоянных данных не добавляли.
- `test:db` проверяет настоящий PostgreSQL, уникальность и SQL rollback. После успеха или ошибки удаляет только созданный этим запуском случайный test-проект; постоянного test-volume нет. Это технический smoke-test, не тест ещё не написанных CRM-сервисов.

Доступ к Docker socket нужен пользователю запуска. Не менять права socket на общедоступные ради обхода ошибки. Настройка доступа к Docker требует осознанных административных прав.

## Проверки и результаты

Проверено локально:

- До добавлений: 233/233 существующих теста, TypeScript, ESLint, форматирование.
- После добавлений: 248/248 тестов, включая 15 новых проверок изоляции, TypeScript и ESLint.
- PostgreSQL local healthy; порт опубликован только на loopback.
- Одноразовый PostgreSQL smoke-test прошёл, его контейнер/network удалены; рабочие данные отсутствовали.
- Gitleaks: вся история Git и текущие неигнорируемые tracked/untracked-файлы. Приватные ignored env не копируются и не выводятся; отсутствие находок не является математическим доказательством отсутствия любых секретов.
- Production-сборка на Node 22 прошла через `npm run build -- --webpack` с отключёнными GAS/Upstash credentials в процессе сборки.

Ограничение сборки: первый запуск без сетевого разрешения не загрузил Google Fonts. После разрешения сети default Turbopack всё ещё блокировался sandbox при создании служебного TCP-порта. Webpack успешно собрал приложение; основной `build`-скрипт не заменён и default Turbopack не объявляется проверенным в этом окружении. Зависимость сборки от внешних шрифтов остаётся отдельной задачей перед production.

CI дополнен закреплённым Node, redacted Gitleaks, генерацией отдельной test-конфигурации и PostgreSQL smoke-test. Workflow не использует production secrets и не выполняет deployment. Изменённый workflow проверен локально по составляющим; запуск на GitHub не производился.
